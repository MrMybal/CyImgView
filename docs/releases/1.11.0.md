## CyImgView 1.11.0

- New searchable metadata workspace, opened with **I** or **Ctrl+I**, with typed values, field presets, add/edit/delete, pending-change reset, clipboard copy and JSON export.
- Bundled native metadata provider using Exiv2, Expat and zlib: EXIF, IPTC, XMP, GPS, comments and ICC profiles. Arbitrary PNG tEXt, zTXt and iTXt records include generation parameters, language, translated keywords and compression options.
- Independent public C ABI for metadata reader/writer DLLs in `plugins/`, alongside the existing image-decoder and editing plugins. The installed-plugins list includes metadata providers.
- Saves use a private same-volume copy, check the source fingerprint, verify written fields and retain a `.metadata-backup` when replacing the original. Save-copy leaves the source intact; failing providers cannot commit their partial output.
- Unicode Windows paths, repeated fields, multilingual XMP and exact hexadecimal values for legacy byte strings. WIC adds container and frame metadata as a read-only supplement.
- English/French interface and offline manual, illustrated workspace guides, provider API reference and save-flow diagram. The same manual is published through GitHub Pages.

### Availability and development

CyImgView remains in active development. This release provides a [Windows x64 installer](https://github.com/MrMybal/CyImgView/releases/download/v1.11.0/CyImgView-1.11.0-Setup.exe) and [portable ZIP](https://github.com/MrMybal/CyImgView/releases/download/v1.11.0/CyImgView-1.11.0-win64.zip). No macOS, Linux or Windows ARM64 build is published.

### Metadata limits

- Metadata writing is format- and group-dependent. Structural fields, WIC-only entries and formats without a suitable writer remain read-only. This release does not make every tag in every supported image format writable.
- Metadata edits apply to the file on disk, independently of unsaved pixel/layer changes. Export `.cyimg` projects to an image first. Metadata edited in the source is not automatically carried into later flattened pixel exports.
- Proprietary maker notes and unsupported encodings or namespaces can require another provider. Exiv2 BMFF formats are mostly read-only, and compressed JPEG XL `brob` metadata is not enabled.
- The new metadata workspace is translated into English and French; other interface languages use English for this workspace.
- Keep the complete `Documentation/` directory beside the executable for offline help. Existing image-format, project-export and browser-storage limits remain documented in the [manual](https://mrmybal.github.io/CyImgView/Documentation.html#/en/overview) and [previous release notes](1.10.2.md#documented-limitations).

### Validation

Native metadata integration and UI checks cover JPEG/PNG/TIFF round trips, Unicode paths, ICC, duplicate fields, XMP arrays, PNG text, source-change detection, backups, pixel preservation and independent failing/crashing providers. Editor regression checks, isolated Windows association tests, documentation validation, package checks and Gitleaks are part of the release verification. This is not an exhaustive compatibility test for every format or proprietary tag.

### Français

- Nouvel éditeur de métadonnées accessible avec **I** ou **Ctrl+I** : recherche, valeurs typées, modèles de champs, ajout/modification/suppression, réinitialisation des changements, copie et export JSON.
- Fournisseur natif intégré basé sur Exiv2, Expat et zlib : EXIF, IPTC, XMP, GPS, commentaires et profils ICC. Les blocs texte PNG tEXt, zTXt et iTXt donnent aussi accès aux paramètres de génération, langues, mots-clés traduits et options de compression.
- API C publique indépendante pour les plugins DLL de lecture et d’écriture de métadonnées dans `plugins/`, à côté des plugins de décodage et d’édition existants. La liste des plugins installés affiche ces fournisseurs.
- Enregistrement sur une copie privée du même volume, vérification de l’empreinte source et des champs écrits, sauvegarde `.metadata-backup` lors du remplacement de l’original. L’enregistrement d’une copie conserve la source ; un fournisseur défaillant ne peut pas valider un résultat partiel.
- Chemins Windows Unicode, champs répétés, XMP multilingue et valeurs hexadécimales exactes pour les anciennes chaînes d’octets. WIC complète la lecture avec les métadonnées du conteneur et des images, en lecture seule.
- Interface et manuel hors ligne français/anglais, guides illustrés, référence API et schéma d’enregistrement. Le même manuel est publié sur GitHub Pages.

#### Limites des métadonnées

- L’écriture dépend du format et du groupe. Les champs structurels, les entrées lues uniquement par WIC et les formats sans moteur adapté restent en lecture seule. Tous les tags de tous les formats lisibles ne deviennent pas modifiables avec cette version.
- Les changements concernent le fichier sur disque indépendamment des modifications de pixels et de calques non enregistrées. Exportez d’abord les projets `.cyimg` vers une image. Les métadonnées modifiées dans la source ne sont pas automatiquement reportées dans les futurs exports de pixels aplatis.
- Certains tags propriétaires, encodages et espaces de noms nécessitent un autre fournisseur. Les formats BMFF d’Exiv2 restent principalement en lecture seule ; les métadonnées JPEG XL compressées `brob` ne sont pas activées.
- Le nouvel éditeur est traduit en français et en anglais ; les autres langues d’interface utilisent l’anglais pour cette fenêtre.
- Conservez tout le dossier `Documentation/` à côté de l’exécutable pour l’aide hors ligne. Les limites existantes des formats d’image, exports de projets et du stockage navigateur restent décrites dans le [manuel](https://mrmybal.github.io/CyImgView/Documentation.html#/fr/overview) et les [notes précédentes](1.10.2.md#limites-documentées).

#### Vérification

Les tests natifs du moteur et de l’interface couvrent les cycles lecture/écriture JPEG/PNG/TIFF, les chemins Unicode, ICC, champs répétés, tableaux XMP, textes PNG, changements de source, sauvegardes, conservation des pixels et fournisseurs indépendants en échec ou plantage. Les vérifications de publication incluent aussi les régressions de l’éditeur, les associations Windows isolées, le manuel, les paquets et Gitleaks. Elles ne constituent pas une validation exhaustive de tous les formats et tags propriétaires.
